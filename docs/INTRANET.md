# 사내 전용 Orca

이 체크아웃은 로그인 없이 로컬 프로필로 사용하는 사내 전용 구성입니다. 사내 SSO(OAuth2)는 아직 구현하지 않았습니다.

## 연결 설정

설정 → **사내 연결**에서 나중에 실제 주소를 입력합니다. 예시에 표시된 회사 주소는 실제 서버가 아닙니다.

| 항목              | 설정 방법                                                                                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 사내 Git·API 서버 | 허용 호스트 목록에 호스트 이름 또는 IP를 한 줄씩 입력합니다. IPv4 CIDR은 /8~ /32를 지원합니다. 프로토콜, 포트, 경로는 넣지 않습니다.                                                                             |
| OpenCode          | 기존 CLI의 모델 자동 검색을 쓰려면 공통 서버 주소와 등록 모델 목록을 모두 비웁니다. 직접 지정하려면 OpenAI 호환 API 주소와 모델 ID를 모두 입력하고 설치된 CLI의 1.x/2.x 설정 형식을 선택합니다.                  |
| OpenCode 인증     | 새 `internal` 공급자의 API 키가 필요하면 키를 보관한 환경 변수 **이름**을 지정합니다. 키 값은 이 화면에 저장하지 않습니다. 공통 서버 주소를 비우고 기존 공급자/모델 ID를 등록하면 기존 공급자 인증을 사용합니다. |
| Claude Code       | Anthropic 호환 사내 게이트웨이 주소와 모델을 입력합니다. 비워 둔 항목은 기존 CLI 설정을 사용합니다. `ANTHROPIC_AUTH_TOKEN` 등의 기존 인증 환경 변수는 유지합니다.                                                |

저장한 값은 새로 시작하는 세션부터 적용됩니다. OpenCode 주소와 등록 모델 목록을 모두 지워 저장하면 Orca가 추가했던 기본 모델 지정도 해제됩니다. 실행 중인 세션을 바꾸거나 사용자의 CLI 설정 파일을 덮어쓰지는 않습니다.

모델 주소의 호스트는 자동 허용됩니다. localhost, IPv4 루프백·RFC1918 사설 주소와 IPv6 루프백·ULA 주소도 기본 허용됩니다. 그 밖의 서버는 정확한 호스트 이름/IP 또는 IPv4 CIDR로 등록해야 합니다. 와일드카드·도메인 접미사 허용은 지원하지 않습니다.

## 제거한 진입점

- Orca 로그인, 외부 공급자 로그인, 클라우드 커넥터와 푸시·릴레이 시작
- 모바일·브라우저 페어링과 데스크톱의 외부 네트워크 수신 (SSH 서버의 루프백 전용 런타임 통신은 허용)
- 외부 작업 서비스, 공개 공유·게시, 온라인 플러그인 설치 UI
- 자동 업데이트·CLI 다운로드, 외부 사용량 조회, 피드백 업로드와 사용 통계 전송
- 외부 사이트 도움말 링크 및 관련 채팅 명령 제안

앱의 에이전트 목록은 OpenCode 1.x/2.x와 Claude Code로 제한합니다. 터미널, 파일·편집기, 로컬 Git 작업, 로컬 스킬과 자동화는 유지합니다.

## 외부 통신 구현 제거

외부 서비스의 전송 구현을 소스에서 제거했습니다. 기능 플래그로 기존 요청 코드를 가리는 방식에만 의존하지 않습니다.

- PostHog 전송, 자동 업데이트, 외부 사용량 조회, 진단·피드백 업로드의 요청 구현을 제거했습니다. `posthog-node`와 `electron-updater` 의존성도 제거했습니다.
- Orca Cloud 인증·커넥터·푸시·릴레이, Google·Linear·Composio 연동의 전송 구현과 관련 RPC 등록을 제거했습니다. Linear SDK는 기존 선언 타입에만 사용하며 개발 의존성으로 옮겼고, SSH 런타임 번들에 복사하는 단계도 제거했습니다.
- 별도의 클라우드 서버와 모바일 클라이언트 실행 소스를 삭제했습니다. 데스크톱이 참조하는 공통 계약 7개는 `src/shared/connectors/contract`로 옮겼으며 클라우드 패키지 의존성도 제거했습니다. 기존 설정을 읽기 위한 호환 API는 남겼습니다. 제거된 기능의 호환 API는 결과 없음 또는 기능 미포함 오류를 반환하며 원래 네트워크 구현을 포함하지 않습니다.
- 공개 CLI 설치 스크립트, 공개 Node·음성 모델 다운로드 주소, Chrome Web Store 다운로드, 기본 공개 플러그인 카탈로그를 제거했습니다.
- Claude·Codex의 공개 계정 로그인 프로세스를 실행하던 구현과 로그인 RPC 등록을 제거했습니다. 이미 설정한 사내 CLI 인증을 사용합니다.
- 외부 검색엔진 주소 생성, Google 파비콘·공개 GitHub 아바타 폴백, 시각화의 CDN 허용 목록, 고정된 외부 사이트 탐색 호출을 제거했습니다. 설치된 로컬 아이콘·언어·테마는 유지합니다.

`pnpm check:intranet-source`는 앱 소스의 알려진 공개 서비스 기본 주소, 제거 영역의 전송 함수·클라이언트 생성, 금지한 SDK의 런타임 의존성, 삭제한 클라우드·모바일 실행 소스의 재유입을 검사합니다. 이는 사내 검사기 자체를 실행한 결과나 모든 동적 통신의 증명은 아닙니다. 문서·라이선스 URL, JWT claim·issuer 식별자, SVG 네임스페이스 및 저장된 URL을 인식하기 위한 문자열은 통신 호출과 구분하여 유지합니다.

사용자가 지정하는 사내 모델·Git·SSH·미러 주소와 로컬 IPC 통신은 계속 지원합니다. 별도 Git·OpenCode·Claude Code·MCP 프로그램의 소스나 기존 설정은 Orca에서 수정하지 않으므로 해당 프로그램도 사내 설정을 사용해야 합니다.

## 여러 모델 선택

사내 연결의 OpenCode 목록에서 **모델 추가**를 누르고 모델 ID·표시 이름·용도를 등록합니다. **새 세션의 기본 모델**에서 기본값을 선택합니다.

- 공통 모델 서버 주소가 있으면 API 모델 ID(예: `coder`, `reasoner`)를 등록합니다. 해당 서버에 `internal/coder`, `internal/reasoner` 공급자 모델을 구성합니다.
- 서버 주소를 비우면 기존 OpenCode 설정의 전체 ID(예: `company/coder`, `company/reviewer`)를 등록합니다. 기존 공급자와 인증은 유지합니다.
- 각 채팅/에이전트의 모델 선택 메뉴에서 다른 등록 모델을 선택할 수 있습니다. 작업자 시작 시에도 모델을 따로 지정할 수 있습니다. 용도는 선택 메뉴에 표시하는 설명이며 자동 분배 규칙이 아닙니다.
- 모델 설명만 바꿔 저장할 때 이미 선택한 다른 모델을 덮어쓰지 않습니다. 삭제한 모델을 기본값으로 사용 중이었다면 현재 등록한 기본 모델로 바꿉니다. 진행 중인 세션은 그대로 유지합니다.

## SSH와 오케스트레이션

설정 → **SSH 호스트**에서 사내 서버를 추가합니다. 호스트 이름으로 접속할 경우 사내 연결의 허용 호스트에도 실제 접속 호스트와 점프 호스트를 등록합니다. 기존 OpenSSH 인증·호스트 키 검증을 사용합니다.

Orca는 이미 로컬/SSH 호스트의 작업자 실행, 작업 상태 조회, 수신함, 작업 결과 전달을 구현하고 있습니다. 이 구성은 SSH 서버의 Orca 런타임을 `127.0.0.1` 또는 `::1`에만 바인딩하고 SSH 터널로 연결합니다. 데스크톱의 모바일·브라우저 접속이나 전체 네트워크 수신은 열지 않습니다. 서버에도 이 사내 빌드의 Orca 런타임 번들과 Node.js를 준비해야 합니다. 기존 공개 릴리스에는 외부 CLI 연결 API가 없을 수 있습니다. 원격 서버에서 curl·wget으로 다시 다운로드하던 폴백 코드를 삭제했습니다. Node 준비는 이 컴퓨터의 사내 미러 또는 SHA-256 검증을 통과한 오프라인 캐시를 사용한 뒤 SSH로 업로드합니다. 미러가 없고 캐시도 없으면 파일을 배치할 경로를 안내합니다.

서버의 CLI와 사내 모델 인증은 그 서버에도 준비해야 합니다. 서버의 기존 OpenCode 모델은 해당 호스트의 모델 선택 메뉴에서 사용합니다. 이 PC에서 복사한 실행 경로는 SSH 서버의 경로가 아닙니다.

## 다른 터미널의 OpenCode·Claude Code 연결

설정 → 사내 연결 → **외부 터미널 연결**에서 해당 CLI 형식을 선택하고 MCP 설정을 복사해 기존 설정에 병합합니다. OpenCode 1.x/2.x와 Claude Code 형식을 각각 제공합니다. 다른 MCP 설정을 통째로 덮어쓰지 마세요. MCP 서버를 다시 연결하거나 해당 CLI를 재시작하면 **최근 연결된 MCP 클라이언트**에 이름과 수신 주소가 나타납니다.

SSH 서버에서 실행한 외부 CLI는 그 서버의 `orca external-agent-mcp --agent opencode` 또는 `--agent claude`를 등록합니다. 필요하면 `--user-data <그 서버의 Orca 프로필 경로>`를 지정합니다. 로컬 CLI가 저장된 SSH 서버를 대상으로 연결하려면 `--environment <서버 선택자>`를 사용할 수 있습니다. 같은 서버/프로필에 연결해야 같은 참여자와 수신함을 봅니다. 여러 호스트를 함께 사용하려면 MCP 항목을 `orca-local`, `orca-gpu`처럼 서로 다른 이름으로 등록하고 각 항목의 `--environment` 또는 프로필 경로를 지정합니다. 에이전트는 각 연결의 도구로 해당 호스트의 참여자를 조회하고 작업과 결과를 전달합니다.

외부 CLI에게 다음과 같이 요청할 수 있습니다.

> orca_list_agents로 참여자를 확인하고, 리뷰 담당에게 orca_send로 변경 사항을 검토해 달라고 보내 줘. orca_receive로 결과를 기다리고, 처리한 메시지는 orca_ack로 확인해 줘.

| MCP 도구           | 동작                                      |
| ------------------ | ----------------------------------------- |
| `orca_identity`    | 자신의 회신 주소 확인                     |
| `orca_list_agents` | 연결된 외부 CLI와 Orca 터미널 조회        |
| `orca_send`        | 다른 참여자에게 작업·상태·결과 전달       |
| `orca_receive`     | 자신의 미확인 메시지 조회, 최대 25초 대기 |
| `orca_ack`         | 처리한 메시지를 확인 처리                 |

Orca 안의 에이전트도 `orca orchestration send --to external:<연결 ID> --subject ... --body ...`로 보낼 수 있습니다. 외부 CLI의 전용 인증값은 MCP 프로세스가 보관하며 목록이나 복사용 설정에 노출하지 않습니다. 메시지는 기존 오케스트레이션 DB에 저장하고 명시적으로 확인할 때까지 보관합니다. 수신 주소·인증은 같은 프로필의 Orca 재시작 뒤에도 유효하고 MCP 프로세스가 주기적으로 연결 상태를 갱신합니다.

이 연결은 도구를 사용하는 협업 방식입니다. 이미 실행 중인 임의의 TUI에 키 입력을 주입하거나, 모든 클라이언트에서 모델의 새 턴을 자동으로 시작하는 기능을 의미하지 않습니다. 에이전트가 수신 도구를 호출해야 작업을 읽습니다. 연결 목록은 최근 2분 이내 갱신한 세션을 표시합니다. CLI가 종료되거나 연결 갱신이 끊기면 최대 2분 뒤 목록에서 사라집니다. 실제 사내 모델 응답과 사내 SSH 호스트 인증은 해당 환경에서 별도로 확인해야 합니다.

## 사내 MCP·스킬·지식체계

`설정 → 사내 연결`에서 다음 연결을 등록하고 아래 **연결 저장**을 누릅니다. 새 OpenCode·Claude Code 세션에 적용되며 실행 중인 세션은 다시 시작해야 합니다.

- **사내 MCP 서버**: HTTP 주소 또는 이미 설치된 stdio 실행 명령과 인수를 등록합니다. 용도는 업무 도구/지식 검색 중 선택할 수 있습니다. 용도는 관리용 분류이며 MCP 도구의 권한을 바꾸지는 않습니다. 토큰은 값 대신 환경 변수 이름을 저장하고, 실제 값은 에이전트 호스트의 환경에 설정합니다. 기본 인증은 Bearer이며 OAuth·사용자 정의 헤더가 필요한 서버는 기존 CLI 설정을 사용합니다. 자동 공개 패키지 설치·카탈로그 검색·OAuth 로그인을 추가하지 않습니다.
- **사내 스킬·문서**: 로컬·공유 폴더와 이름을 등록합니다. 내장 `orca intranet-resources-mcp`가 활성화된 폴더를 읽기 전용 MCP로 노출합니다. 스킬 폴더에서는 `SKILL.md`를 조회하고 문서 폴더에서는 키워드를 검색합니다. 스킬을 CLI의 기본 슬래시 명령으로 설치하거나 스크립트를 실행하는 기능은 아닙니다. 보조 텍스트 파일은 읽을 수 있습니다.
- **다른 클라이언트용 설정**: 입력 중인 설정을 OpenCode 1.x/2.x 또는 Claude Code JSON으로 복사합니다. 다른 터미널에서는 기존 파일에 병합하고 MCP를 다시 연결합니다. 기존 Claude `--mcp-config` 인수가 있으면 그것을 유지하므로 해당 파일/JSON에 직접 병합해야 합니다. 기존 설정의 동일한 연결 ID는 Orca에 등록한 활성 연결이 우선합니다. Orca에서 끄거나 삭제해도 별도로 CLI에 직접 저장한 연결은 유지됩니다.

공통 자료 도구는 `company_sources`, `company_list_files`, `company_search`, `company_read`입니다. 에이전트에게 “사내 자료 목록을 확인하고 배포 절차를 검색해 줘”처럼 요청할 수 있습니다. 검색은 문자 그대로의 키워드 검색이며 벡터·의미 검색이나 PDF/Office 추출은 제공하지 않습니다. 지원 형식은 Markdown/MDX/TXT/JSON/YAML/CSV/RST/HTML입니다. 최대 깊이 6, 파일 1,000개, 항목 5,000개, 파일당 64 KiB, 검색 결과 50개까지 처리하며 제한에 걸리면 `truncated`를 반환합니다. 등록 폴더 밖 파일과 바이너리는 거부하고 목록 탐색에서 숨김 폴더·심볼릭 링크·node_modules를 건너뜁니다.

원격 위키·RAG·지식 그래프·문서 플랫폼은 MCP 검색 서버로 연결합니다. REST API만 있는 시스템은 API 규격과 인증 방식이 정해진 뒤 전용 어댑터가 필요합니다. 현재 임의의 API 응답을 지식으로 색인하는 기능은 없습니다.

폴더와 명령은 **에이전트가 실행되는 호스트** 기준입니다. SSH 서버에 세션을 만들면 그 서버에서 폴더에 접근할 수 있어야 하며 최신 Orca CLI와 stdio 서버가 설치되어 있어야 합니다. `Orca CLI 명령`에는 해당 호스트의 실행 파일 경로도 지정할 수 있습니다. 환경 변수나 사내 인증값을 로컬에서 SSH로 자동 복사하지 않습니다. 개발 모드에서 이 PC의 CLI를 직접 호출하려면 `node config/scripts/development/launch/orca-dev.mjs intranet-resources-mcp`를 사용할 수 있습니다.

설정 형식은 [OpenCode MCP 문서](https://opencode.ai/docs/mcp-servers/)와 [Claude Code MCP 문서](https://code.claude.com/docs/en/mcp)를 기준으로 구분합니다. OpenCode 1.x는 `mcp.<id>`, 2.x는 `mcp.servers.<id>`, Claude는 `mcpServers.<id>`를 사용합니다. MCP 등록은 기존 모델 설정을 대체하지 않습니다.

## 사내 Bot

`설정 → Bots`에서 Bot을 켜고 만들 수 있습니다. Bot마다 실행 도구·모델·권한·역할 지침(SOUL.md)·메모리(MEMORY.md)를 설정합니다. 기존 Bot의 홈 채팅, 별도 채팅, 메모리 편집/이력, 작업 항목, 작업 배분과 로컬 자동화 기능을 재사용합니다. 프로젝트를 Bot에 맡기는 화면도 복구했습니다.

- 실행 도구는 이 컴퓨터에 설치된 OpenCode 1.x·2.x, Claude Code, Codex 중 자동 감지하여 선택합니다. 새 Bot은 감지된 도구만 선택하며 설치되지 않은 Claude 로그인 화면을 기본값으로 열지 않습니다. 감지 중·도구 없음·확인 실패를 구분하고 다시 감지하거나 설치 경로 설정으로 이동할 수 있습니다. 다른 CLI도 설치 여부를 조회하지만 Bot 실행 어댑터가 지원하는 도구만 선택할 수 있습니다. 인터넷 설치는 제공하지 않습니다. OpenCode 2.x에는 원본의 지침 전달 수정을 반영하여 기존 사용자 설정을 연결한 별도 설정 폴더의 AGENTS.md로 역할·메모리를 전달합니다. 원본 설정 파일은 덮어쓰지 않습니다.
- 먼저 `설정 → 사내 연결`에 모델을 등록합니다. Codex는 해당 CLI의 기존 사내 서버·인증 설정을 유지하면서 모델 ID·이름·용도·기본값을 여러 개 등록합니다. 사내 연결 화면을 열면 선택된 Codex 홈의 `config.toml`과 `models_cache.json`에서 모델 후보를 자동 감지합니다. 원래 Codex 설정 파일은 수정하지 않으며 Codex 프로세스나 모델 서버를 호출하지 않습니다. 기본 모델·같은 공급자의 프로필 모델·캐시 출처를 구분하며, 다른 공급자의 캐시가 섞일 수 있는 사용자 지정 공급자는 설정 파일의 모델만 표시합니다. 감지한 모델을 선택해 추가한 뒤 연결 설정을 저장하면 Bot에서 사용할 수 있습니다. 캐시만으로 현재 서버의 사용 권한이나 전체 모델 목록을 검증할 수는 없습니다. Bot별 모델을 지정하지 않으면 해당 실행 도구의 등록된 사내 기본 모델을 사용합니다. 일반 채팅에 기억된 모델이나 CLI의 미등록 기본 모델로 넘어가지 않습니다. 모델 미등록·삭제·지원하지 않는 실행 도구는 새 채팅 및 저장된 대화 재실행 시 거부합니다. 채팅 생성이 실패하면 작업 폴더의 기본 터미널로 대신 이동하지 않고 원인과 모델 설정 작업을 표시합니다. 이미 열린 Bot 작업 폴더에는 채팅 오류와 다시 열기 버튼을 표시합니다.
- 사내 연결에 등록한 MCP 서버와 스킬·문서 폴더는 새 Bot 세션에도 적용됩니다. 구형 Bot 전용 도구 파일에 서버가 남아 있으면 그 파일 대신 사내 연결 설정으로 옮겨야 합니다. 외부 도구 인증·중계는 복구하지 않았으며 로컬 CLI의 Bot 식별 토큰만 유지합니다.
- 공유·공개 템플릿 설치·Slack·Linear·Google·Composio·Orca 계정 연결은 복구하지 않았습니다. 자동 살펴보기는 로컬 파일·Git 읽기·Orca 작업 조회 범위에서 제안합니다. 사내 모델 API의 실제 인증과 답변은 사내 환경에서 검증해야 합니다.
- Bot 생성과 권한 변경은 소유자의 앱 화면에서 수행합니다. 에이전트 CLI가 임의로 Bot을 만드는 기존 제한은 유지합니다. Bot의 실행 호스트·등록 모델·설치된 CLI를 맞춰야 하며 다른 SSH 서버의 경로와 인증을 자동 복사하지 않습니다.

Bot은 선택한 실행 도구와 모델을 사용하는 지속적인 역할·작업 관리 기능입니다. 별도의 Orca 전용 모델이나 모든 화면을 임의로 조작하는 중앙 에이전트는 아닙니다. CLI와 오케스트레이션이 지원하는 프로젝트·터미널·세션 조회와 작업 배분 범위에서 동작합니다.

## 폐쇄망 준비

승인된 OpenCode/Claude Code 실행 파일과 사용하는 공급자 어댑터·플러그인·MCP 의존성을 사내 배포 절차로 미리 설치해야 합니다. Orca는 필요한 CLI를 인터넷에서 대신 다운로드하지 않습니다. 회사 인증서와 CLI 인증은 각 도구의 기존 설정을 사용합니다.

Orca의 Node HTTP/TCP와 Electron 요청·외부 링크에는 사내 호스트 정책을 적용합니다. 이 정책은 운영체제 방화벽이 아니며, 터미널에서 실행하는 Git·에이전트·MCP 등 별도 프로세스의 통신을 강제로 격리하지 않습니다. 해당 도구의 모델·웹 검색·업데이트·플러그인 설정과 사내 네트워크의 외부 통신 차단도 함께 적용해야 합니다. CLI 자체의 내장 메뉴는 Orca가 수정하지 않습니다.

개발 모드에는 로컬 Vite 서버와 루프백 CDP 디버깅 포트가 있습니다. 이 개발용 접속과 로컬 에이전트 훅/IPC는 다른 기기의 앱 접속 기능과 별개입니다. 배포 시에는 개발 서버 대신 빌드 결과를 사용합니다.

## 이 PC에서 다시 실행

개발 도구는 시스템 Node와 분리하여 `%LOCALAPPDATA%\orca-dev-tools`에 설치했습니다. 해당 폴더의 `start-orca-dev.cmd`를 실행하면 이 체크아웃을 개발 모드로 띄웁니다. 서버를 중지하려면 실행한 터미널에서 Ctrl+C를 누릅니다.

개발 의존성까지 설치된 환경의 명령은 `pnpm dev`, 타입 검사는 `pnpm tc`, 데스크톱 번들 빌드는 `pnpm build:electron-vite`입니다. 설치 파일 패키징은 별도 단계입니다.

설정 형식 참고: [OpenCode MCP](https://opencode.ai/docs/mcp-servers/), [Claude Code MCP](https://code.claude.com/docs/en/mcp), [OpenCode 공급자](https://opencode.ai/docs/providers/), [OpenCode 설정](https://opencode.ai/docs/config/), [Claude Code 환경 변수](https://code.claude.com/docs/en/env-vars).
